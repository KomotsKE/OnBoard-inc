# backend — API платформы

FastAPI + SQLAlchemy 2.0 в асинхронном режиме ([ADR-0010](../docs/adr/0010-async-backend.md)),
PostgreSQL 16, миграции Alembic.

## Структура

```
app/
  main.py          приложение, lifespan, middleware запроса, /health
  core/
    config.py      класс Settings — единственная точка доступа к настройкам
    logging.py     JSON-логи, request_id, журнал значимых операций
    errors.py      доменные исключения и ответы по RFC 9457
    deps.py        зависимости FastAPI: сессии публичного и панельного контуров
  db/session.py    движок, фабрика сессий, транзакция на запрос
  api/v1/public/   эндпоинты виджета (без JWT, по public_key)
  api/v1/panel/    эндпоинты панели (JWT)
  models/          SQLAlchemy-модели
  schemas/         схемы запросов и ответов
  services/        бизнес-логика, не знающая про HTTP
tests/             зеркалят структуру app/
alembic/           миграции
```

## Запуск

Бэкенд поднимается вместе со стеком из корня репозитория:

```bash
make up                       # postgres, миграции, api, стенд
curl localhost:8000/health    # {"status":"ok","db":"ok"}
```

Миграции применяет одноразовый сервис `migrate`, от успешного завершения которого
зависит `api` — подробности в [guides/migrations.md](../docs/guides/migrations.md).

Код смонтирован в контейнер, поэтому правка видна после
`docker compose restart api`. Пересборка образа нужна только при изменении
зависимостей в `pyproject.toml`.

## Тесты

```bash
make test                     # pytest внутри контейнера api
```

Тесты асинхронные (`asyncio_mode=auto`), клиент — `httpx.ASGITransport`: сеть не
поднимается, но `lifespan` выполняется, поэтому движок и пул создаются как в бою.

**База для тестов отдельная** — имя рабочей плюс `_test`. Она создаётся при первом
прогоне, миграции применяются один раз на сессию, а каждый тест выполняется во
внешней транзакции, которая откатывается после него. Сессии приложения на время
теста подменяются фабрикой, привязанной к тому же соединению
(`join_transaction_mode="create_savepoint"`), поэтому запись, сделанную через HTTP,
тоже уносит откат — даже если сервис внутри вызвал `commit()`.

Фикстура проверяет, что имя базы заканчивается на `_test`: промахнуться и
отработать по рабочим данным нельзя.

Данные создаются фабриками из `tests/factories.py`, а не вручную в теле теста.

## Что важно знать перед правками

**Настройки** читаются только через `get_settings()` (§13.1
[conventions.md](../docs/conventions.md)). Префикс переменных — `ONBOARD_`:
он отделяет настройки приложения от переменных compose в том же `.env`. Опечатки
в именах ловит `unknown_settings_keys()`, а не `extra="forbid"`: тот проверяет
только файл и молча пропускает переменную окружения с опечаткой — проверено
прогоном. Секреты — `SecretStr`, поэтому не печатаются в логах и стектрейсах.

**Сессия БД** берётся зависимостью `PublicSession` или `PanelSession`: они
отличаются `statement_timeout` (2 с против 5 с, §9.1
[vision.md](../docs/vision.md)). Одна транзакция на запрос, и коммитит её
`TransactionMiddleware` **до отправки ответа**: зависимости с `yield` в FastAPI
закрываются уже после, и коммит на их выходе означал бы, что API подтверждает
запись раньше, чем она зафиксирована (§12.1а
[conventions.md](../docs/conventions.md)). Сервисы не коммитят сами.

**Ошибки**: сервисы поднимают исключения из `core/errors.py` и ничего не знают
про HTTP; перевод в `application/problem+json` живёт в одном обработчике.

**Логи** — JSON в stdout. Значимые операции пишутся через `log_event()` после
успешного коммита. В логи не попадают пароли, токены и `Set-Cookie` (§9.3
[vision.md](../docs/vision.md)).

**Асинхронность** накладывает ограничения: в `async def` нет блокирующих
вызовов, CPU-тяжёлое (argon2) выносится в поток, связи SQLAlchemy грузятся явно
через `selectinload` (§12 [conventions.md](../docs/conventions.md)).
