# e2e — сквозные сценарии на Playwright

Проверяют виджет и панель в настоящем браузере против стенда `testsite/`, никогда
против внешних сайтов (§7 [conventions.md](../docs/conventions.md)).

## Запуск

```bash
make e2e        # поднимает стек, наполняет демо-данными и прогоняет сценарии
```

Первый запуск скачивает Chromium (~150 МБ). Отдельно, если стек уже поднят:

```bash
cd e2e && npx playwright test
cd e2e && npx playwright test --headed      # посмотреть глазами
cd e2e && npx playwright show-trace test-results/<папка>/trace.zip
```

## Что важно знать

**Стек поднимает `make e2e`, а не Playwright.** Конфиг, который сам управляет docker,
при падении сценария оставляет стек в непонятном состоянии.

**Данные — из `make seed`.** Сценарии опираются на демо-проект с ключом из сниппета
стенда и на тур, показываемый на путях с префиксом `/reports`. Своих данных через API
они не создают: тогда пришлось бы держать в них второй набор правды о схеме.

**Ретраев нет.** Флака в сценарии против локального стенда означает настоящую гонку
в виджете, и прятать её повтором — худшее, что можно сделать. Если сценарий мигает,
причина ищется в коде или в самом сценарии: первая версия `loader.spec.ts` подписывалась
на ответ конфига после навигации и ловила его не всегда.

**Проверяем по списку сетевых запросов, а не по картинке.** Главное свойство
двухэтапной загрузки — то, чего *не* происходит: на странице без тура ядро не
скачивается ([ADR-0001](../docs/adr/0001-two-stage-widget-loading.md)). Увидеть это
можно только в сетевых запросах.
