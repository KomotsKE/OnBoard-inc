# Введение в проект

Документ для того, кто открыл репозиторий впервые. Здесь всё, чтобы поднять
стек, пройти тур на стенде и понять, где что лежит, — без обращения к другим
файлам. Когда понадобятся подробности, их адреса собраны в конце.

## Что это такое

OnBoard — платформа интерактивного онбординга. Две половины:

- **виджет** — один тег `<script>` на сайте клиента, который показывает поверх
  его интерфейса пошаговые подсказки: подсвечивает элемент и объясняет, что с ним
  делать;
- **панель** — кабинет владельца сайта, где он собирает туры и смотрит, где люди
  теряются.

Ценность в том, что тур собирает сам владелец сайта, без разработчиков, а
разработчика просят ровно один раз — вставить тег.

## Как устроено

```
         сайт клиента                     наш стек
  ┌───────────────────────┐      ┌──────────────────────────┐
  │  loader.js  (1 КБ)    │─────▶│  GET /v1/public/config   │  есть ли тур
  │     │ есть тур?       │      │                          │  для этого адреса
  │     ▼                 │      │                          │
  │  core.js   (7 КБ)     │─────▶│  POST /v1/public/events  │  события прохождения
  │  Shadow DOM: подсветка│      └────────────┬─────────────┘
  │  SVG-маской + подсказка│                  │
  └───────────────────────┘                   ▼
                                       ┌──────────────┐
   панель владельца  ──────────────────│  PostgreSQL  │
   React + TanStack Query  JWT + cookie└──────────────┘
```

Ключевые решения, которые объясняют почти весь код:

| Решение | Зачем |
|---|---|
| Загрузчик и ядро — разные файлы | на странице без тура ядро не скачивается вовсе |
| Весь UI виджета — в Shadow DOM | чужой CSS не ломает подсказку, наш не ломает сайт |
| Подсветка — SVG-маска, а не `z-index` | элементы клиента не трогаем совсем |
| Публичный контур — по ключу проекта и `Origin` | ключ виден в исходниках страницы, поэтому домен проверяется всегда |
| Access-токен панели — только в памяти | XSS не уносит доступ на месяц |
| События — батчами, идемпотентно | сеть рвётся, вкладки закрываются, доставка повторяется |

## Поднять за пять минут

Нужны только Docker с Compose и GNU Make.

```bash
make up          # postgres, миграции, api, панель, стенд с виджетом
make seed        # демо-владелец, проект, четыре тура и события
```

`make up` создаст `.env` из шаблона. Секреты в нём нерабочие — для локальной
работы этого достаточно, но перед первым запуском можно подставить свои:

```bash
python3 -c "import secrets; print('ONBOARD_JWT_SECRET=' + secrets.token_urlsafe(48))"
python3 -c "import secrets; print('ONBOARD_EDITOR_TOKEN_SECRET=' + secrets.token_urlsafe(48))"
```

Что где открывается:

| Адрес | Что это |
|---|---|
| http://localhost:5173 | панель; вход `demo@onboard.local` / `demo-onboard-password` |
| http://localhost:8080/reports | стенд: сайт клиента с враждебным CSS и вставленным тегом |
| http://localhost:8000/health | проверка живости API |

Откройте http://localhost:8080/reports — поверх страницы появится подсказка
первого шага. Пройдите тур кнопкой «Далее»: это и есть продукт целиком.

## Добавить шаг тура

1. Панель → **Проекты** → «Отчётница (стенд)» → **Туры** → «Знакомство
   с отчётами» → **Конструктор**.
2. Внизу списка шагов: селектор элемента и текст подсказки. На стенде есть
   готовые цели, например `[data-testid="dark-target"]` или
   `[data-testid="scrolled-target"]`.
3. **Добавить шаг** — он появится в списке; порядок меняется перетаскиванием
   (мышью или с клавиатуры: Tab до ручки, пробел, стрелки, пробел).
4. Откройте http://localhost:8080/reports заново — новый шаг на месте.

Так же проверяется всё остальное: поменяли цвет в **Оформлении** — обновили
стенд, увидели новый цвет; прошли тур — в **Аналитике** выросли числа.

## Где что лежит

```
backend/     FastAPI: публичный контур виджета, API панели, аналитика
  app/api/v1/public/   конфиг виджета и приём событий (без JWT, по ключу проекта)
  app/api/v1/panel/    всё, что требует входа
  app/services/        бизнес-логика, не знает про HTTP
  app/models/          таблицы, по файлу на агрегат
  alembic/             миграции, единственный способ менять схему
  scripts/seed.py      демо-данные
panel/       React + TypeScript
  src/pages/           по экрану на файл
  src/hooks/           запросы к API через TanStack Query
  src/api/client.ts    единственное место, где живёт fetch и обновление токена
widget/      TypeScript без зависимостей
  src/loader/          то, что исполняется на чужой странице сразу
  src/core/            движок тура: поиск цели, подсветка, подсказка, события
testsite/    стенд: намеренно враждебный CSS, SPA-навигация, отложенные элементы
e2e/         сквозные сценарии Playwright: tests/widget и tests/panel
docs/        документация (список — в конце)
```

## Команды

```
make up / make down / make logs      стек
make seed                            демо-данные
make test                            pytest + vitest панели и виджета
make e2e                             Playwright против стенда и панели
make lint                            ruff + tsc
make size                            бюджет размера бандлов виджета
make migrate / make revision m="…"   миграции
make hooks / make commits            git-хуки и проверка сообщений коммитов
```

Правило: новая функциональность проверяется одной из этих команд. Нет команды —
нет проверки.

## Как здесь принято работать

- **Задача берётся из [tasklist.md](tasklist.md)** — там же её критерий приёмки
  в строке «проверка». Отметка `[→]` означает «в работе»; одновременно в работе одна.
- **Решение, которое дорого менять, оформляется записью в [adr/](adr/)**, а не
  правкой документа задним числом.
- **Замеченная по пути проблема идёт в «Замечания»** того же tasklist, а не
  исправляется молча в чужой задаче.
- **Комментарий объясняет «почему»**, а не пересказывает код.
- **Коммиты — Conventional Commits** со ссылкой `Refs: T3.4`; проверяется хуком.

Подробно — [conventions.md](conventions.md) (как писать код) и
[workflow.md](workflow.md) (цикл задачи, матрица проверок, что делать, если
сессия прервалась).

## Если что-то не поднялось

| Симптом | Причина и что делать |
|---|---|
| `make up` жалуется на переменные окружения | нет `.env` — `make env`, затем `make up` |
| порт занят | поменяйте `POSTGRES_PORT`, `API_PORT`, `PANEL_PORT` или `TESTSITE_PORT` в `.env` |
| стенд отдаёт 404 на `/widget/loader.js` | бандлы не собраны: `make size` соберёт их и проверит бюджет |
| панель показывает экран входа после правок бэкенда | `docker compose restart api` — код смонтирован, но uvicorn не перечитывает его сам |
| регистрация отвечает 429 | сработал настоящий лимит (5 в час с адреса); счётчики в памяти процесса, сбрасываются перезапуском `api` |
| в консоли сайта `[OnBoard] …` | виджет сообщает о своей проблеме: он никогда не бросает исключений в чужую страницу |
