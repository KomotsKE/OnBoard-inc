# ADR-0002: Весь UI виджета — в Shadow DOM

Статус: принято · Дата: 2026-10-12 · Задачи: T2.4, T2.8

## Контекст

Наш интерфейс рендерится внутри чужого документа, про CSS которого мы не знаем ничего.
Реальные сайты содержат `* { box-sizing: border-box }`, tailwind preflight, bootstrap,
глобальные сбросы шрифтов, `!important` и селекторы по тегам. Любой из них способен
развалить подсказку; симметрично, наши стили способны развалить сайт клиента.

## Решение

Один хост-элемент — прямой потомок `<body>` с `all: initial`, `position: fixed`,
`z-index: 2147483000`, внутри — открытый shadow root. Все стили виджета живут внутри
shadow root (`adoptedStyleSheets`, при недоступности — `<style>` внутри shadow root).
В документ клиента не добавляется ни одного правила CSS.

## Альтернативы и почему отвергнуты

- **Префиксы классов (`.onboard-*`) в общем документе.** Защищает от коллизий имён,
  но не защищает от селекторов по тегам, глобальных сбросов и `!important` клиента.
- **`<iframe>` для подсказки.** Изоляция идеальная, но позиционирование относительно
  элементов страницы и наследование шрифта бренда становятся болезненными, плюс вес.
- **Closed shadow root.** Чуть строже, но лишает нас возможности писать e2e-проверки
  по содержимому подсказки.

## Последствия

- Темизация идёт через CSS-переменные, пробрасываемые в shadow root (см. T6.1).
- Проверяем в тестах: после запуска тура в `document.head` клиента не появилось
  ни одного нашего `<style>`; подсказка корректна на стенде с враждебным CSS.
- Это не паритет с рынком, а преимущество: по измерениям §3.3
  [competitors.md](../competitors.md) признаки работы с shadow root нашлись только у
  Usetiful; driver.js, shepherd.js, intro.js и ядро Userflow изолируют стили
  префиксами классов и потому уязвимы к глобальным сбросам CSS на сайте клиента.
- Ограничение: `position: fixed` внутри трансформированных предков ведёт себя иначе,
  поэтому хост монтируется именно в `<body>`, а не рядом с целевым элементом.
