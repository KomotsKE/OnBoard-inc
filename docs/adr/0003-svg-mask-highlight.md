# ADR-0003: Подсветка элемента — SVG-маска, а не подъём по z-index

Статус: принято · Дата: 2026-10-12 · Задачи: T2.3

## Контекст

Нужно затемнить страницу и выделить один элемент, оставив его кликабельным.
Распространённый приём — поднять целевой элемент над затемнением через
`position: relative; z-index: 9999`.

## Решение

Элемент клиента не трогаем вообще. Поверх страницы рисуем `<svg>` во всю область
просмотра с затемняющим прямоугольником и «окном» в маске по
`getBoundingClientRect()` цели, `pointer-events: none` на оверлее. Геометрия
пересчитывается на `scroll`, `resize` и через `ResizeObserver` с троттлингом по `rAF`.

## Альтернативы и почему отвергнуты

- **Подъём элемента по z-index.** Требует менять `position` и `z-index` чужого
  элемента. Ломает `position: sticky` у хедеров, рушит порядок наложения внутри
  трансформированных контейнеров и в stacking context'ах, а после закрытия тура
  нужно аккуратно восстанавливать исходные значения — источник трудноуловимых багов
  на сайте клиента. Нарушает инвариант «не вмешиваемся в DOM клиента».
- **Четыре `div`-шторки вокруг элемента.** Не даёт скругления и плавного перехода,
  на дробных координатах оставляет щели.
- **`backdrop-filter` + вырез.** Поддержка и производительность хуже, выигрыша нет.

## Последствия

- Целевой элемент остаётся полностью интерактивным: отверстие не перехватывает
  события, пользователь может нажать кнопку, о которой рассказывает подсказка.
- Проверяем в e2e: клик по подсвеченной кнопке стенда вызывает обработчик сайта;
  снимок атрибутов целевого элемента до и после запуска тура совпадает.
- Стоимость: собственный код пересчёта геометрии при скролле и анимациях страницы.
