## Этап 1 — ядро бэкенда

- [ ] **T1.1 Аутентификация**
  Регистрация, вход, refresh, logout; argon2, JWT access 15 мин в теле ответа +
  refresh 30 дней в httpOnly cookie с ротацией ([ADR-0008](adr/0008-session-storage.md)).
  *проверка:* pytest — успешный вход; неверный пароль → 401; повторная регистрация → 409;
  протухший access → 401; refresh по cookie без тела выдаёт новый access; повторное
  использование ротированного refresh → 401 и сессия закрыта; logout делает cookie
  непригодной.

- [ ] **T1.2 Проекты**
  CRUD, генерация `public_key`, `allowed_origins`, `theme` со значениями по умолчанию.
  *проверка:* pytest — CRUD; `public_key` уникален; дефолтная тема присутствует в ответе.

- [ ] **T1.3 Изоляция арендаторов как слой**
  Зависимости `get_current_user`, `get_owned_project`, `get_owned_tour` — фильтрация
  по `user_id` внутри запроса к БД.
  *проверка:* pytest — матрица 2 пользователя × 2 проекта × все приватные маршруты;
  чужой объект → 404 (не 403, не 200).

- [ ] **T1.4 Туры**
  CRUD, `publish`/`unpublish`, валидация `url_match` (включая проверку regex на
  компилируемость и запрет катастрофического бэктрекинга простым лимитом длины).
  *проверка:* pytest — публикация меняет статус и `published_at`; невалидный regex → 422.

- [ ] **T1.5 Шаги**
  CRUD + изменение порядка одной транзакцией.
  *проверка:* pytest — после `PUT /steps/order` позиции 0..N−1 без дыр и дублей;
  параллельный reorder не ломает уникальность.

- [ ] **T1.6 Сниппет установки**
  `GET /projects/{id}/snippet` — готовый тег со `data-key` и `data-api`.
  *проверка:* pytest — ответ содержит актуальный `public_key` и адрес API из настроек.

## Этап 2 — виджет

- [ ] **T2.1 Loader**
  Чтение `data-key`/`data-api`, запрос конфига, ленивая загрузка `core.js` только при
  наличии подходящего тура, `widget_ping`.
  *проверка:* e2e — на странице без тура `core.js` не запрашивается (проверяем по
  списку сетевых запросов); с туром — запрашивается один раз.

- [ ] **T2.2 ElementResolver**
  Поиск по селектору, ожидание появления через MutationObserver (таймаут 10 с),
  проверка видимости, отслеживание перемещения.
  *проверка:* vitest — элемент есть / появляется через 2 с / не появляется (таймаут →
  событие `step_target_missing`); e2e на динамическом элементе стенда.

- [ ] **T2.3 Оверлей с подсветкой**
  SVG-маска с «окном» вокруг цели, затемнение, рамка цветом темы, пересчёт при
  скролле и ресайзе.
  *проверка:* e2e — клик по подсвеченной кнопке стенда вызывает обработчик сайта
  (отверстие не перехватывает события); при скролле окно остаётся на элементе;
  DOM стенда не изменён (снимок атрибутов целевого элемента до/после).

- [ ] **T2.4 Tooltip**
  Подсказка в Shadow DOM, собственное позиционирование с flip/shift, мобильная
  раскладка < 480 px.
  *проверка:* e2e — 4 позиции на стенде с враждебным CSS; на 375 px ширине подсказка
  не выходит за экран; в документ клиента не добавлено ни одного `<style>`.

- [ ] **T2.5 TourEngine**
  Шаги, «Далее»/«Назад»/«Пропустить»/«Готово», прогресс в localStorage, `show_once`,
  продолжение тура после перехода на другую страницу.
  *проверка:* e2e — полный проход 4 шагов; скип на шаге 2; после перезагрузки тур не
  показывается повторно; при отключённом localStorage тур проходится (деградация).

- [ ] **T2.6 Доступность**
  `Esc` = пропустить, фокус-трап, стрелки, `aria-live`, контраст.
  *проверка:* e2e с клавиатуры без мыши; axe-core без критичных нарушений.

- [ ] **T2.7 Поддержка SPA**
  Обёртка `pushState`/`replaceState` + `popstate`, перепроверка `url_match`.
  *проверка:* e2e — переход по SPA-роуту стенда запускает тур без перезагрузки;
  оригинальный `pushState` продолжает работать (счётчик вызовов сайта не сломан).

- [ ] **T2.8 Защитный контур**
  `try/catch` на всех точках входа, `textContent` для текстов, один глобал,
  работа при недоступном API.
  *проверка:* vitest — текст шага `<img src=x onerror=alert(1)>` не исполняется;
  e2e — при заблокированном API сайт работает, в консоли нет необработанных ошибок;
  снимок `window` до/после отличается только на `OnBoard`.

  Регистрация, вход, `AuthProvider` с access-токеном в памяти, восстановление сессии

## Этап 4 — аналитика

- [ ] **T4.1 Приём событий**
  `POST /public/events`: батч, валидация, проверка `Origin` против `allowed_origins`,
  идемпотентность по `event_id`, rate limit, всегда 204 при валидном ключе.
  *проверка:* pytest — двойная отправка одного батча → одна строка в БД; чужой Origin
  → 403; битая схема события → 204 и событие отброшено (виджет не ретраит).

- [ ] **T4.2 Отправка событий из виджета**
  Буфер, флаш по таймеру и размеру, `sendBeacon` на `visibilitychange`, повтор из
  localStorage.
  *проверка:* e2e — закрытие вкладки посреди тура доставляет `tour_started` и
  `step_viewed`; при недоступном API события уходят при следующей загрузке.

- [ ] **T4.3 Агрегация**
  `GET /tours/{id}/analytics` — тоталы, воронка по шагам, drop-off, проблемные шаги,
  период `from`/`to`.
  *проверка:* pytest на фикстуре из 10 прогонов (3 завершения, 5 скипов, 2 обрыва) —
  все числа совпадают с посчитанными вручную по формулам §7.2 vision.md.

- [ ] **T4.4 Экран воронки**
  Четыре тотала, воронка по шагам, подсветка худшего шага, блок «Проблемы».
  *проверка:* e2e — после 10 прогонов на стенде числа в UI совпадают с ожидаемыми.
