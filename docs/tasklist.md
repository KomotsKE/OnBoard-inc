## Этап 1 — ядро бэкенда

- [x] **T1.1 Аутентификация**
  Регистрация, вход, refresh, logout; argon2, JWT access 15 мин в теле ответа +
  refresh 30 дней в httpOnly cookie с ротацией через `refresh_sessions`
  ([ADR-0008](adr/0008-session-storage.md), §3.1 [data-model.md](data-model.md)).
  Политика пароля — §5.1 [data-model.md](data-model.md): 12–128 символов, без правил
  состава, блок-лист top-10000. Хэширование argon2 выносится в поток
  (`anyio.to_thread`), иначе вход блокирует event loop (§12.5 conventions.md).
  *проверка:* pytest — успешный вход; неверный пароль → 401; повторная регистрация → 409;
  протухший access → 401; refresh по cookie без тела выдаёт новый access; повторное
  использование ротированного refresh → 401 и сессия закрыта; logout делает cookie
  непригодной; пароль из блок-листа и пароль короче 12 символов → 422; пароль
  в 100 символов с пробелами принимается; в логах есть `user.login.failed` с причиной
  и **без email**, `auth.refresh.reuse_detected` уровня ERROR при повторном
  использовании токена; 11-я попытка логина с одного IP → 429
  с `Retry-After`; 6-я неудачная попытка по одному email → 429 даже с другого IP
  (§9.2 [vision.md](vision.md)).

- [x] **T1.2 Проекты**
  CRUD включая `DELETE` (каскад), генерация `public_key`, `allowed_origins`, `theme`
  со значениями по умолчанию, лимиты из §5 [data-model.md](data-model.md), эндпоинт
  `snippet`. Списковый ответ — в конверте `{items, next_cursor}` (§12.8 conventions.md).
  **Зависимость `get_owned_project` создаётся здесь и используется с первого маршрута** —
  изоляция не дописывается потом, иначе первый же забытый обработчик станет утечкой.
  *проверка:* pytest — CRUD; `public_key` уникален; дефолтная тема присутствует в ответе;
  пустой `allowed_origins` → публичный конфиг отвечает отказом (fail closed);
  11-й проект на пользователя → 422.

- [x] **T1.3 Изоляция арендаторов: матрица проверок**
  Зависимости созданы в T1.2 и T1.4; здесь — полная матрица тестов и запрет прямого
  `session.get` в обработчиках панели (проверяется ревью диффа и grep в тесте).
  *проверка:* pytest — матрица 2 пользователя × 2 проекта × все приватные маршруты;
  чужой объект → 404 (не 403, не 200).

- [x] **T1.4 Туры**
  CRUD, `publish`/`unpublish`, валидация `url_match` (включая проверку regex на
  компилируемость и запрет катастрофического бэктрекинга простым лимитом длины);
  `GET /tours/{id}` отдаёт тур со шагами; список туров проекта возвращает `runs_7d`
  и `completion_rate_7d` одним агрегатом (§6 [screens.md](screens.md)).
  *проверка:* pytest — публикация меняет статус и `published_at`; невалидный regex → 422;
  публикация тура без шагов → 422; архивный тур не попадает в публичный конфиг;
  список из 3 туров отдаётся одним запросом с метриками; тест на число SQL-запросов
  фиксирует константу — N+1 не проходит (§12.6 conventions.md).

- [x] **T1.5 Шаги**
  CRUD + изменение порядка одним `UPDATE ... CASE` (уникальность объявлена
  `DEFERRABLE`, §3.2 [data-model.md](data-model.md)); удаление последнего шага
  опубликованного тура снимает тур с публикации и возвращает новый статус (§8.2
  [vision.md](vision.md)).
  *проверка:* pytest — после `PUT /steps/order` позиции 0..N−1 без дыр и дублей;
  перестановка шага с 3-й позиции на 1-ю проходит одним оператором;
  два конкурентных reorder одного тура не нарушают уникальность.

- [x] **T1.6 Сниппет установки**
  `GET /projects/{id}/snippet` — готовый тег со `data-key` и `data-api`.
  *проверка:* pytest — ответ содержит актуальный `public_key` и адрес API из настроек.

## Этап 4 — аналитика

- [x] **T4.1 Приём событий**
  `POST /v1/public/events`: батч одним `INSERT ... ON CONFLICT` без
  предварительного `SELECT`, проверка `Origin`, идемпотентность по `event_id`,
  обрезка URL до пути, лимит 100/мин за интерфейсом `RateLimiter`, 429
  с `Retry-After`, иначе всегда 204. Тело разбирается независимо от
  `Content-Type`: `sendBeacon` шлёт `text/plain`, и это поведение браузера,
  а не наш выбор (понадобится в T4.2).
  *проверка:* `make test`, 13 тестов — двойная отправка одного батча даёт одну
  строку; число запросов не растёт с размером батча; query-строка не
  сохраняется; битое событие отброшено с ответом 204 (повтор его не починит);
  чужой Origin → 403; неизвестный ключ → 404; батч сверх лимита и конверт без
  ключа → 422; превышение лимита → 429 с `Retry-After`. Проверено на живом
  стеке: повтор батча не создаёт второй строки, в журнале видно
  `stored=1` и затем `duplicates=1`.

- [x] **T4.2 Отправка событий из виджета**
  Буфер с флашем по таймеру и размеру, `sendBeacon` на `visibilitychange`,
  повтор с нарастающей задержкой, отложенный батч в localStorage с TTL сутки;
  `device` через `matchMedia`, User-Agent не разбирается. Закрыты долги T2.5
  и T2.8: движок шлёт `step_target_missing`, `report` — `widget_error` с кодом.
  *проверка:* `make test` — 14 тестов отправки и 5 тестов событий движка:
  батч по таймеру и по размеру, повтор на 429 с нарастающей задержкой, выход
  в localStorage после исчерпания повторов, протухший батч не отправляется,
  на 4xx повторов нет, `sendBeacon` на скрытии вкладки, uuid без
  `crypto.randomUUID`. `make e2e` — события уходят одним батчем с общим
  `run_id`; уход со страницы посреди тура доставляет накопленное; при
  недоступном API события уходят при следующей загрузке; на 429 повтор несёт
  те же события.

- [x] **T4.3 Агрегация**
  `GET /tours/{id}/analytics?range=7d|30d` — тоталы, воронка по шагам,
  drop-off, проблемный шаг, блок «Проблемы», скользящее окно в UTC. Один SQL
  с агрегатами; в Python перебираются только строки агрегата.
  *проверка:* `make test`, 13 тестов на фикстуре из 10 прогонов (3 завершения,
  5 скипов, 2 обрыва) — все числа совпадают с посчитанными вручную по формулам

  тоталы и воронка считаются по одной границе; событие с чужим `tour_id`
  в свою воронку не попадает; число запросов не растёт с числом событий.
  Проверено на живых данных: 36 запусков, 13 завершений, проблемный шаг
  подсвечен.

- [x] **T4.4 Экран воронки**
  Тоталы, воронка по шагам с подсветкой худшего, блок «Проблемы»,
  переключатель периода 7/30 дней, пустое состояние с подсказкой, что

  *проверка:* `make test` — проблемы формулируются словами с селектором и

## Этап 5 — editor-mode

- [x] **T5.1 Сессия редактора**
  `POST /tours/{id}/editor-session` с `mode: edit|preview` → url + токен
  (TTL 15 мин, скоуп — один тур). В запрос добавлен `page_url`: в проекте хранятся
  разрешённые домены, а не страницы, и угадать нужную сервер не может — его origin
  обязан быть в `allowed_origins`. Контракт в §8.2 vision.md описывал только `mode`,
  дописан. Два пункта проверки переехали в T5.2, где появляется потребитель токена:
  HTTP-отказ 401 по просроченному токену и отличие `preview` от `edit` на стороне
  ingest — предъявлять токен пока некуда.
  *проверка:* `make test` — 13 тестов: чужой и несуществующий тур → 404, адрес вне
  `allowed_origins` и неразбираемый адрес → 422, query и `#hash`-маршрут страницы
  сохраняются, скоуп и режим читаются из токена, просроченный токен и access-токен
  панели не читаются как токен редактора.

- [x] **T5.2 Публичные эндпоинты редактора**
  Чтение тура по токену, создание/правка/удаление шагов. Логика шагов не
  дублируется — маршруты вызывают `services/steps.py`, поэтому лимит в 20 шагов,
  сжатие позиций и автоснятие с публикации работают и из редактора. Мутации идут
  обычным JSON, поэтому добавлен обработчик `OPTIONS`: трюк с `text/plain` из
  `/public/events` не спасает, `PATCH` и `DELETE` вызывают preflight всегда.
  Токен превью читает тур, но на мутацию отвечает 403 — объект свой, отказ по
  режиму; для этого в `core/errors.py` появился общий `ForbiddenError`. Заодно
  закрыто замечание про лимитер: общий `check` переехал в `core/rate_limit.py`.
  Ошибки контура отдаются без CORS-заголовков, как и весь публичный контур, —
  решать в T5.4, когда у них появится читатель.
  *проверка:* `make test` — 16 тестов: шаг, созданный по токену, виден в панели;
  шаг другого тура → 404; просроченный и негодный токен → 401; удалённый тур →
  404; чужой origin → 403; токен превью не меняет шаги (POST/PATCH/DELETE → 403);
  лимит 60/мин → 429; preflight отвечает 204 с Allow-Methods.

- [x] **T5.3 Генератор селекторов**
  Приоритеты по §5 vision.md, фильтрация хэш-классов, требование уникальности.
  Машинные имена отсеиваются по форме (часть из букв с цифрами длиной от
  четырёх), а не по словарю: `step-2` и `col-md-6` остаются. Правила написаны
  на свойствах Unicode — `\w` считает буквой только латиницу, и класс
  `кнопка-выгрузки` для него выглядел машинным. `CSS.escape` не понадобился:
  генератор берёт только готовые идентификаторы CSS.
  *проверка:* vitest на наборе DOM-фикстур — `data-testid`, осмысленный id,
  сгенерированный id (`#__next_a1b2`), классы CSS-модулей (`css-1q2w3e`, `_btn_a1b2`),
  глубокая вложенность без атрибутов; для каждого случая селектор находит ровно один элемент.

- [x] **T5.4 Пикер элементов**
  `editor.js`: подсветка под курсором, показ селектора, форма шага, панель со списком
  шагов, выход из режима. Клик по сайту гасится в фазе перехвата — иначе выбор
  ссылки уводил бы со страницы, а выбор кнопки отправлял форму сайта. Ответ
  `editor-session` получил `editor_url`: загрузчик знает только токен, а имя
  файла с хэшем — в манифесте сборки (ADR-0009). Токен ищется и в записи
  навигации, а не только в `location`: сниппет стоит с `async`, и SPA успевает
  срезать query своим `replaceState` — ровно это делает стенд. В режиме
  редактора тур не показывается; при негодном токене не показывается и он —
  страница открыта не для посетителя. Предпросмотр (`mode=preview`) здесь
  только распознаётся, запуск тура — T5.6.
  *проверка:* `make e2e` — клик по кнопке стенда создаёт шаг, селектор из него
  находит на странице ровно один элемент, шаг виден в панели через API; клик по
  ссылке не уводит со страницы; «Готово» убирает редактор; с негодным токеном
  не появляется ни редактор, ни тур. Плюс `make test` — 17 юнит-тестов пикера,
  панели и разбора токена, и `make size`: editor.js 3.6 КБ из 20 КБ.

- [x] **T5.5 Связка с панелью**
  Кнопка «Выбрать на сайте», обновление списка шагов по `window.focus`. Рядом
  с кнопкой — поле адреса страницы: в проекте хранятся домены, а не страницы.
  Вкладка открывается по нажатию, до ответа сервера, иначе браузер блокирует
  её как всплывающее окно. Кроме `refetchOnWindowFocus` (он слушает
  `visibilitychange` и ловит возврат на вкладку) добавлен слушатель `focus`:
  если панель в соседнем окне, видимость не меняется и перезапроса не было бы.
  *проверка:* `make e2e` — шаг, добавленный в соседней вкладке на стенде,
  появляется в конструкторе после возврата; без разрешённого домена вместо
  формы подсказка. Возврат в окно приходится посылать событием: headless
  Chromium не гасит вкладки одного контекста, поэтому ни `visibilitychange`,
  ни `focus` сами не приходят — остальная цепочка в сценарии настоящая.

- [x] **T5.6 Предпросмотр тура на своём сайте** (задача J5, желательно в MVP)
  Кнопка «Превью» в конструкторе открывает сайт с токеном редактора в режиме
  предпросмотра: тур проходится целиком, события аналитики не пишутся. Тур
  проходит обычное ядро, а не отдельный показ внутри редактора: вторая
  реализация означала бы вторую правду о том, как тур выглядит. Шаги берутся
  из ответа сессии, а не из публичного конфига, — иначе черновик, ради
  которого превью и нужно, посмотреть было бы нельзя. В этом режиме ядро не
  трогает ни аналитику, ни localStorage, а `show_once` снимается: владелец
  смотрит столько раз, сколько нужно. Ответ сессии получил `core_url`
  к уже имевшемуся `editor_url`.
  *проверка:* `make e2e` — проход тура в превью не делает ни одного запроса
  к `/v1/public/events`, и воронка тура после него показывает ноль запусков;
  кнопка «Превью» недоступна для тура без шагов.

## Этап 8 — редизайн панели

Направление выбрано: вариант 2 из макетов — консоль с постоянной навигацией
проекта слева. Источник значений — дизайн-система OnBoard (артефакт Claude
Design), в код она переносится руками: сборочного шага из JSON в CSS нет,

## Замечания

Сюда попадает всё, что замечено по пути, но не входит в текущую задачу: несвязанные
проблемы, долги, идеи. Не правим молча — записываем.

- **`storageState` Playwright несовместим с ротацией refresh-токенов.** Снимок
  cookie можно предъявить один раз: второй контекст с той же cookie для бэкенда
  выглядит как кража токена, и вся цепочка гасится (ADR-0008) — так и задумано.
  Поэтому панельные сценарии не переиспользуют сессию, а группируют утверждения:
  один вход на сценарий. Это же ограничение действует для T3.2–T3.6.
- **Подпись кнопки «Назад» не берётся из темы.** В `theme` есть `next_label`,
  `skip_label` и `done_label`, а «Назад» зашита в код: кнопка появилась в T2.5,
  уже после того, как схему темы согласовали. Поле `back_label` добавляется без
  миграции (тема — JSONB), но это изменение контракта темы — делать вместе
  с первой просьбой клиента, а не заранее.
- **Фокус-трап не пускает к подсвеченному элементу с клавиатуры.** Tab ходит по
  кругу внутри подсказки, поэтому дойти клавишами до самой подсветки нельзя —
  для информационных туров это верно, но шаг «нажмите эту кнопку» клавиатурой
  не пройти. Решать, когда появятся шаги с действием; варианты — включать цель
  первой остановкой в круге или отключать трап для таких шагов.
- **Лимитер считает всех за одним прокси как один IP.** `_client_ip` в
  `api/v1/panel/auth.py` берёт `request.client.host`, а панель ходит к API через
  прокси vite внутри compose — значит 10 регистраций в час делятся между всеми,
  кто регистрируется через панель, а не выдаются каждому. За реальным обратным
  прокси будет то же самое: `X-Forwarded-For` нигде не разбирается. Лимит подняли
  с 5 до 10, но это обход, а не решение. Чинить вместе с выносом на сервер
  (§15 [vision.md](vision.md)), когда появится известный список доверенных прокси:
  доверять заголовку без него — способ обойти любой лимит подменой адреса.
- ~~**Маршруты аутентификации не пишут `rate_limit.exceeded`.**~~ Закрыто в T5.2:
  маршруты редактора стали третьим потребителем, общий `check` переехал
  в `core/rate_limit.py` и пишет отказ сам: через него ходят регистрация, вход,
  обновление токена, публичный конфиг, приём событий и маршруты редактора.
  Лимит неудачных входов по email остался отдельным — он пополняется по исходу,
  а не по факту запроса, — но запись в журнал теперь делает и он.
- ~~**Экран «Оформление» недостижим из интерфейса.**~~ Закрыто в T8.2:
  разделы проекта живут в постоянной боковой навигации, ссылка на оформление
  есть с любого экрана проекта.
- **Логотип объявлен дважды и читается дважды.** В `AppLayout.tsx` у SVG стоит
  `role="img" aria-label="OnBoard"` рядом с текстом «OnBoard» — диктор произносит
  название два раза. В `AuthLayout.tsx` это исправлено (`aria-hidden`), в шапке
  консоли — нет: файл вне границ T8.7. Чинить вместе, одной правкой.
- **Снимки экрана входа весят 278 и 191 КБ** и отдаются без хэша в имени.
  Для LCP-элемента первого экрана многовато: качество 75 или ширина 1600 снимут
  больше половины без видимой разницы. Замена файла не сбросит кеш у тех, кто уже
  входил, — решать вместе с раздачей статики (§15 vision.md).
- **Потеря между шагами видна только мышью.** В воронке drop-off лежит
  в `title=` у значения строки: с клавиатуры и экранным диктором он недоступен,
  хотя S9 docs/screens.md обещает воронку с drop-off. У худшего шага он продублирован
  текстом, у остальных — нет. Вывод в разметку меняет содержание экрана, поэтому
  в T8.6 (оформление) не вошёл.
- **Три одинаковые коробки в стилях панели.** `.card`, `.install__block`
  и `.step-form` имеют попиксельно одинаковые рамку, радиус и padding. По правилу
  трёх дублирование пора убирать: перевести два старых класса на `.card`.
- **Мёртвый класс `page`.** `BrandingPage.tsx` и `InstallPage.tsx` ставят
  `className="… page"`, но правила `.page` в `styles.css` нет (появилось в T8.5).
- **`!important` по привычке.** Остались в `styles.css` около строк 290, 644, 649,
  845, 850 — тот же приём, что сняли в тоталах T8.6: конкурирующего правила нет,
  специфичности класса достаточно.
- **Сырые пиксели вне контракта токенов.** `scripts/check-styles.py` стережёт только
  цвета и тени; размеры шрифтов и ширины по всей панели остались в px. Либо
  расширять проверку, либо честно признать, что контракт T8.1 про цвет, а не про размер.
- **Классы styled-components генератор селекторов не отсеивает.** `sc-bdVaJa`
  и `jsXBcL` не содержат цифр, поэтому под правило «машинного имени» (T5.3)
  не попадают и могут попасть в селектор. Ловить их пришлось бы угадыванием
  «случайности» имени, а это делает правило непредсказуемым. Страховка та же,
  что и у остальных уровней: проверка уникальности и ручная правка селектора
  в панели. Пересмотреть, если такие селекторы начнут ломаться у клиентов.
- **У типа события `widget_ping` нет отправителя.** Статус «виджет подключён»
  считается по `widget_last_seen_at`, который обновляет сам запрос конфига — отдельный
  запрос с сайта клиента на каждую загрузку страницы ради тех же данных был бы
  лишним. Решить в T4.1: либо тип убирается из перечисления миграцией, либо
  начинает отправляться с какой-то отдельной целью.
- ~~**Ошибки самого FastAPI не в формате RFC 9457.**~~ Закрыто в T1.1: добавлены
  обработчики `StarletteHTTPException` и `RequestValidationError`; 404, 405 и 422
  отдаются как `application/problem+json`, значения полей в ответ не попадают.
  Проверяется `tests/test_error_format.py`.
