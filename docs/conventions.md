# Соглашения по разработке

Версия: 1.0 · Дата: 2026-10-12

Как мы пишем код в этом проекте. Жёсткие инварианты, нарушение которых блокирует
задачу, — в [../CLAUDE.md](../CLAUDE.md); здесь они не дублируются. Что мы строим —
[vision.md](vision.md). Этот документ описывает стиль и структуру, а не архитектуру.

---

## 1. Структура репозитория

```
backend/
  app/
    api/v1/public/      эндпоинты для виджета (без JWT, по public_key)
    api/v1/panel/       эндпоинты панели (JWT)
    core/               config.py, security.py, deps.py
    db/                 session.py, base.py
    models/             SQLAlchemy-модели, по одному файлу на агрегат
    schemas/            Pydantic-схемы запросов и ответов
    services/           бизнес-логика, не зависящая от FastAPI
  alembic/              миграции
  tests/                тесты, зеркалят структуру app/
panel/
  src/api/              клиент API и типы ответов
  src/pages/            по одному файлу на экран из §4.3 vision.md
  src/components/       переиспользуемые куски UI
  src/hooks/            хуки TanStack Query
widget/
  src/loader/           точка входа loader.js
  src/core/             движок тура: engine, resolver, overlay, tooltip, analytics
  src/editor/           режим выбора элементов
  tests/                vitest
testsite/               стенд с враждебным CSS для проверки виджета
e2e/                    Playwright-сценарии
docs/                   idea, vision, adr, conventions, workflow, tasklist, guides
```

Новый каталог верхнего уровня — повод обсудить, а не создать молча.

Репозиторий один (монорепо), наружу `backend/`, `panel/` и `widget/` публикуются как
зеркала поддеревьев — [ADR-0007](adr/0007-monorepo-with-subtree-publishing.md). Поэтому:

- коммит по задаче может затрагивать несколько компонентов — это нормально и желательно;
- код не шарится между компонентами через относительные импорты вверх
  (`../../backend/...`): после публикации поддерева такой импорт окажется битым.
  Общее — только через HTTP-контракт;
- адреса внешних репозиториев живут в `.env`, а не в `Makefile`.

## 2. Python

- ruff как линтер и форматтер, длина строки 100.
- Типы на всех публичных функциях. `Any` — только с комментарием, почему иначе нельзя.
- SQLAlchemy 2.0: `Mapped[...]` / `mapped_column(...)`, без legacy-`Column`.
- Слои: обработчик FastAPI парсит вход и вызывает `services/`; бизнес-логика в
  обработчиках не живёт. Исключение — тривиальный CRUD без логики, он может быть
  в обработчике целиком.
- Имена схем: `ProjectCreate`, `ProjectUpdate`, `ProjectRead`. Модель и схема никогда
  не называются одинаково.
- Зависимости FastAPI — в `core/deps.py`, по одной на сущность
  (`get_current_user`, `get_owned_project`, `get_owned_tour`).
- Исключения: `HTTPException` поднимаем только в слое API; сервисы поднимают
  собственные типы или возвращают результат.
- Настройки — только через `core/config.py` (pydantic-settings). `os.getenv` в коде
  приложения не используется.

## 3. Миграции

- Только Alembic, только через `make revision m="…"`.
- Каждая миграция обязана откатываться: `downgrade` пишется и проверяется, а не
  оставляется с `pass`.
- Миграция входит в ту же задачу, что и модель, которую она обслуживает.

## 4. API

- Версия в пути: `/v1/...`. Публичные маршруты — под `/v1/public/`, остальные
  требуют JWT.
- Коды: 200/201 — успех, 204 — ingest событий, 401 — нет или просрочен токен,
  403 — запрещённый Origin, 404 — объект не найден **или** не принадлежит
  пользователю, 409 — конфликт уникальности, 422 — ошибка валидации.
- Ответы — всегда Pydantic-схемы, никогда `dict` «как получилось».
- Публичный API виджета не ломает обратную совместимость: на чужих сайтах живут
  старые версии скрипта. Поля только добавляются.

## 5. React (панель)

- Функциональные компоненты, хуки. Классовых компонентов нет.
- Серверное состояние — только TanStack Query; локальное — `useState`.
  Redux, MobX, Zustand и прочие сторы не добавляем.
- Access-токен — только в памяти провайдера, никогда в `localStorage`
  ([ADR-0008](adr/0008-session-storage.md)). В `localStorage` панели не хранится
  ничего, кроме UI-мелочей (последний выбранный проект, свёрнутые блоки).
- Обработка 401 и refresh живут в одном месте — `src/api/client.ts`. В хуках и
  компонентах проверок «а не истёк ли токен» нет.
- Запросы к API — только через `src/api/` и хуки в `src/hooks/`; `fetch` внутри
  компонента запрещён.
- Ключи запросов — по соглашению из §4.6 vision.md, от общего к частному; инвалидация
  по префиксу, а не `invalidateQueries()` без аргументов.
- У каждого экрана обработаны три состояния: загрузка, ошибка, пусто. Белый экран
  при ошибке запроса — дефект.
- Один экран = один файл в `src/pages/`. Компонент длиннее ~200 строк делится.
- Стили — CSS-модули, без UI-библиотек (цель — не тащить дизайн-систему в MVP).
- Строки — по-русски прямо в разметке, без i18n-словарей.

## 6. Виджет

- ES2020, без полифилов и транспиляции в ES5.
- Ноль рантайм-зависимостей. Любая внешняя библиотека в виджете — отдельное
  обсуждение с замером влияния на бюджет размера.
- Модули — фабрики, возвращающие объект с методами (`createTooltip(...)`), без
  классов и наследования.
- Публичная поверхность — только `window.OnBoard` с методами `start`, `stop`, `version`.
- Все слушатели событий снимаются при остановке тура; `ResizeObserver` и
  `MutationObserver` отключаются. Утечка наблюдателей на SPA накапливается молча.
- Логи — `console.debug` с префиксом `[OnBoard]`, и только их. Ни `console.log`,
  ни `console.error` на сайте клиента.

## 7. Тесты

- Имя теста описывает поведение: `test_foreign_project_returns_404`, а не `test_project_2`.
- Один тест проверяет одно утверждение. Длинные сценарные проверки — в e2e.
- Фикстуры данных — в `tests/factories.py`; тела тестов не заполняют БД вручную.
- E2E работают против стенда `testsite/`, никогда против внешних сайтов.
- Что покрываем обязательно, а что не покрываем — [workflow.md §6](workflow.md).

## 8. Запрещено

- Добавлять зависимости вне списка в CLAUDE.md без согласования.
- Выполнять SQL в БД руками, в обход миграций.
- Использовать `innerHTML` для пользовательского контента.
- Коммитить `.env`, дампы БД, `node_modules`, артефакты сборки.
- Писать в БД события с IP, email или сырым User-Agent.
- Оставлять закомментированный код «на всякий случай» — для этого есть git.
- Рефакторить код, не относящийся к текущей задаче.
- Создавать абстракцию под одно использование.
