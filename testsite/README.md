# testsite — стенд для проверки виджета

Статический сайт, на котором проверяется встраиваемый виджет. Отдаётся nginx из
`docker-compose.yml` на `http://localhost:8080`.

## Зачем нужен

Виджет работает на чужих страницах, про CSS которых мы не знаем ничего. Стенд —
намеренно враждебная среда: если виджет корректен здесь, он корректен почти везде.
Сборка не нужна, никаких зависимостей — только `index.html`, `app.js` и
`styles/hostile.css`.

## Что на нём воспроизведено

| Случай | Где | Что проверяет |
|---|---|---|
| `* { margin: 0; box-sizing: border-box }` | `hostile.css` | подсказка не зависит от сброса стилей (tailwind preflight) |
| Типографика через `!important` | `hostile.css` | изоляция в Shadow DOM, а не борьба важностями |
| `button, input { all: unset }` | `hostile.css` | наши кнопки выживают за счёт изоляции |
| Sticky-хедер | `.site-header` | виджет не поднимает элементы по `z-index` (ADR-0003) |
| Контейнер с `transform: translateZ(0)` | `.transformed` | containing block ломает `position: fixed` внутри |
| Чужой виджет с `z-index: 2147483000` | `.rival-bubble` | порядок наложения без войны за максимум |
| Модальное окно сайта | `#modal`, кнопка «Фильтры» | подсказка не ломает чужую модалку |
| Прокручиваемый контейнер | `.scrollbox` | подсветка пересчитывает положение при прокрутке |
| Тёмная секция | `.dark-section` | контраст подсветки и подсказки на тёмном фоне |
| Элемент появляется через 2 с | `#export` в `app.js` | ожидание элемента вместо «шаг сломан» (T2.2) |
| Страница с единственной отложенной целью | маршрут `/delayed` | подсветка доезжает до элемента, которого при загрузке не было |
| Страница с туром `show_once` | маршрут `/once` | пройденный тур не возвращается после перезагрузки |
| Неизвестный путь заменяется на `/reports` | `app.js`, `replaceState` | адрес меняется раньше, чем выполнится async-загрузчик |
| SPA-навигация `pushState` + `popstate` | `app.js` | обёртка над History API (T2.7) |
| Элементы с `data-testid` | хедер, кнопки | генератор селекторов предпочитает стабильные атрибуты |
| Классы вида `css-1q2w3e`, `_btn_a1b2c` | `hostile.css` | генератор отбрасывает сгенерированные имена (T5.3) |
| Сниппет вставлен дважды | `reports-twice.html` | один запуск виджета: один запрос конфига, одно ядро, один оверлей |

Тег виджета вставлен ровно так, как его вставляет клиент — `data-key` и `data-api`.
Проект с этим `public_key` создаётся командой `make seed`, и он же разрешает домен
`http://localhost:8080`: без записи в `allowed_origins` конфиг отвечает 403 (fail
closed). Демо-тур показывается на путях с префиксом `/reports`, поэтому `/settings` —
страница без тура, на которой ядро не должно запрашиваться.

## Запуск

```bash
make up                     # поднимает стенд вместе со стеком
curl -I localhost:8080      # 200 OK
```

Файлы монтируются только для чтения, поэтому правка видна после перезагрузки
страницы — пересобирать контейнер не нужно. Бандлы виджета монтируются отдельно
из `widget/dist` и отдаются по `/widget/` с заголовками кэша из
[ADR-0009](../docs/adr/0009-widget-cache-and-versioning.md).

Стенд отдаётся как SPA: прямой заход на `/dashboard` возвращает `index.html`,
иначе проверить навигацию без перезагрузки было бы нельзя.

## Правила правок

**Враждебность — это ценность стенда, а не недостаток.** Упрощать CSS, чтобы
«виджет выглядел лучше», нельзя: смысл в том, чтобы он выглядел правильно в плохих
условиях. Новый случай добавляется вместе со строкой в таблице выше.
